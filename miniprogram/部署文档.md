# PrintGate 部署文档（服务端 + 微信小程序）

> 适用版本：`Printgate-最终版` 服务端 v2.0.0 + 小程序端 v4（`小程序最新端26.10.23`）。
> 本文覆盖：服务端容器化部署、打印机接入、微信小程序侧配置、三种网络场景、安全加固、升级回滚、运维排障。

---

## 0. 前提条件

| 项 | 要求 |
| --- | --- |
| 服务端系统 | Linux x86_64 / arm64（Windows/macOS 仅适合本地联调，AirPrint 与部分 USB 不可用） |
| 容器运行时 | Docker 20.10+ 与 docker compose 插件 |
| 打印机 | USB（需挂 `/dev/bus/usb`）或网络 IPP / AirPrint / RAW |
| 微信小程序 | 已注册的 AppID（**不能用 touristappid**）、完成主体认证与类目设置 |
| 网络 | 公网场景需已备案域名 + 443 可用 |

小程序端工程目录：`小程序最新端26.10.23/`（用微信开发者工具导入其中 `project.config.json`）。

---

## 1. 架构与端口

```
微信小程序 ──HTTPS──▶ PrintGate :8080 ──▶ CUPS ──▶ 打印机
                          │
                          ├─ 管理台 SPA（Vue3） 同一端口
                          ├─ SQLite（/data/printgate.db，WAL）
                          ├─ 上传/扫描件/预览（/data/files、/data/scans、/data/preview）
                          └─ frpc（可选，内网穿透）
```

| 端口 | 用途 | 是否需要对外 |
| --- | --- | --- |
| 8080 | 管理台 + 全部 `/api/*`（**小程序只连这个**） | 是 |
| 631 | CUPS IPP / AirPrint | 局域网内可选 |
| 9100 | 虚拟打印机接收器（无实体机时验证链路） | 否，可不映射 |

数据卷：

| 卷 | 内容 | 备份重要性 |
| --- | --- | --- |
| `./data:/data` | 数据库、上传文件、扫描件、头像、frp 配置、预览缓存 | **高** |
| `./cups:/etc/cups` | 打印机队列与驱动配置 | **高**（不挂则容器重建后队列丢失） |

## 2. 服务端部署

### 2.1 Docker Compose（推荐）

```bash
cd Printgate-最终版/Printgate
docker compose up -d --build
# 打开 http://127.0.0.1:8080
```

默认 compose 已包含 `restart: unless-stopped`、健康检查（`/api/health`，30s 间隔）、数据卷映射。

### 2.2 纯 docker run

```bash
docker build --platform linux/amd64 -t printgate:alpine .
docker run -d --name printgate --restart unless-stopped \
  -p 8080:8080 -p 631:631 \
  -v "$PWD/data:/data" -v "$PWD/cups:/etc/cups" \
  printgate:alpine
```

ARM 设备（N1 / 树莓派 / armbian）：

```bash
docker buildx build --platform linux/arm64 -t printgate:alpine . --load
```

### 2.3 常用构建参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `WITH_OFFICE=1` | `0` | 内置 LibreOffice，开启后 docx/xlsx/pptx 可直接上传转 PDF（镜像显著变大） |
| `CACHEBUST=$(date +%s)` | `0` | 只改了前端 `web/` 却看不到变化时用它强制重编前端 |
| `NODE_TAG` | `22-alpine` | 运行时基础镜像 |

> 更换镜像后必须重建容器，否则容器仍挂在旧镜像上（`docker ps` 不会提示）：
> `docker rm -f printgate && docker compose up -d`

### 2.4 USB 打印机 / 扫描仪

`docker-compose.yml` 中放开注释：

```yaml
    devices:
      - /dev/bus/usb:/dev/bus/usb
```

验证：

```bash
docker exec printgate lpstat -p              # 打印机队列
docker exec printgate scanimage -L           # 扫描仪
docker exec printgate scanimage --version
```

### 2.5 AirPrint / mDNS 完整可用

桥接网络下 Avahi 广播与自动发现受限。Linux NAS / 小主机建议改用：

```yaml
services:
  printgate:
    network_mode: host     # 同时删掉 ports 段
```

## 3. 首次配置（按顺序执行）

### 3.1 初始化管理员密码

首屏初始化向导：密码 **≥8 位且同时含字母与数字**，设置后自动登录后台。

### 3.2 打印机

1. **自动扫描**：进入「打印机 → 自动扫描」。容器是桥接网络，默认只看得到 Docker 内网（172.17.x），**务必把「扫描范围」改成路由器局域网网段**，例如 `192.168.1.0/24`（支持多个，逗号分隔）。
2. 扫不到 → 抽屉里「手动探测」直接输入打印机 IP；仍不行用「深度扫描」（额外探测 443/515）。
3. 手动添加：`ipp://IP/ipp/print`（免驱）或 `socket://IP:9100`（RAW/PCL），驱动会按地址自动切换。
4. 没有实体机 → 「创建虚拟打印机」，打印结果落在 `data/spool/`，可先验证整条链路。
5. 打印页 → 「测试页」确认能出纸。

### 3.3 小程序对接参数（唯一维护入口）

后台「小程序对接」页集中维护：

| 项 | 说明 |
| --- | --- |
| AppID / AppSecret | 与小程序端共用同一份，保存后点「测试连通性」 |
| 接入地址 BASE | 公网填 `https://你的域名`；内网留空则用当前访问地址 |
| 管理员 OpenID 白名单 | 可留空；白名单内的微信登录即自动成为管理员 |
| 新用户需审批 / 允许扫码登录 / **开发模式** | 三个开关 |

> **生产环境必须关闭「开发模式」**：开启后 `/api/mp/dev-login` 接受任意 openid，并可借 `adminOpenids` 自动提权，等于可冒用任意身份（详见第 6 节）。

### 3.4 绑定管理员微信

小程序登录页 → 我的（或后台二维码）→ 扫「小程序对接」页右侧二维码 → 该微信立即成为管理员。之后可用「扫码登录」进网页后台。

### 3.5 用户审批策略

新用户首次登录默认**待审批**，到「小程序用户」放行；或提前在「小程序对接」加 OpenID 白名单。

## 4. 微信小程序侧配置

### 4.1 导入工程与替换 AppID

1. 微信开发者工具 → 导入 `小程序最新端26.10.23/`（选择 `project.config.json` 所在目录，AppID 选「使用测试号」以外的正式号）。
2. 编辑 `project.config.json`，把 `"appid": "touristappid"` 换成正式 AppID。
3. **`touristappid` 无法完成真实 `wx.login` 换 token**，真机与体验版必须换成正式 AppID。

### 4.2 服务地址

两处等价：

- **登录页**「服务地址配置」→ 弹层填地址 → 保存并重新连接（未登录时也能改，保存后自动重试）；
- 登录后「我的 → 服务地址」。

优先级：**运行时设置 > Storage 缓存 > `config/index.js` 默认值**。
默认值由 `config/index.js` 的 `current` 决定（当前 `dev` → `http://127.0.0.1:8080`）。上线前建议把它改成正式环境：

```js
// config/index.js
const current = 'prod';
const ENVS = {
  dev:     { name: '本地联调', baseUrl: 'http://127.0.0.1:8080' },
  staging: { name: '预发环境', baseUrl: 'https://staging.你的域名.com' },
  prod:    { name: '生产环境', baseUrl: 'https://print.你的域名.com' }
};
```

### 4.3 服务器合法域名

微信公众平台 → 开发管理 → 服务器域名，把后端域名加入：

| 域名 | 用途 |
| --- | --- |
| `request` | 全部 `/api/*` |
| `uploadFile` | 文件上传、头像上传 |
| `downloadFile` | 文件预览图、头像下载 |

- 必须是 **https + 443**（体验版/开发版可在开发者工具「详情 → 本地设置」勾选**不校验合法域名**临时联调）。
- 域名不支持带端口，公网务必走 443。

### 4.4 用户隐私保护指引（必做）

代码侧已内置 `privacy-modal`，并用**官方** `<button open-type="agreePrivacyAuthorization">` 作为「同意」按钮——只有这个按钮能让微信把「已同意」持久化，自绘按钮只放行当前这一次调用、不记账，下次调隐私接口仍会被拦截。

**还必须在 mp 后台完成**：设置 → 服务内容声明 → 用户隐私保护指引，填写并提交审核，且**逐项勾选**本小程序实际采集的信息：

| 必勾项 | 对应接口 | 不勾的后果 |
| --- | --- | --- |
| 微信聊天文件 | `chooseMessageFile` | 「聊天文件」按钮选不了 |
| 相册（或「图片/视频」） | `chooseImage` | 「图片相册」、发票/身份证选图选不了 |
| 头像 | `chooseAvatar`（open-type） | 换头像点了没反应 |
| 昵称 | `<input type="nickname">` | 昵称填不进去 |
| 摄像头 | `scanCode` | 扫码绑定/登录无响应 |
| 相册（写入） | `saveImageToPhotosAlbum` | 预览图保存失败 |

> 典型症状：用户点了「同意」、弹窗也关了，但聊天文件 / 图片相册 / 换头像**仍然用不了**——八成是后台指引里没勾对应的信息类型，而不是代码问题。勾选后需**重新提交审核并发布新版本**才生效。

自查手段：开发者工具「详情 → 本地设置」确认已开启隐私校验（`app.json` 的 `__usePrivacyCheck__`），清缓存重编译，首次调用隐私接口时应当弹窗一次，同意后**后续同类接口不再弹**。若每次都弹，就是指引没勾全。

### 4.5 类目与审核

- 类目选择与「打印 / 工具 / 效率」相符的类目，确保包含所需能力。
- 体验版不要打开「开发模式」，审核期间也不要用 dev-login。
- 首次提交建议用「开发版」灰度，确认打印链路后再转正式版。

### 4.6 本地联调（开发模式登录）

后台开启「开发模式」后，登录页底部「开发模式登录」可一键模拟登录（固定 openid `dev_local_tester`，重复登录仍是同一账号，审批状态可持久）。**联调结束务必关掉。**

## 5. 三种网络场景

### 5.1 本机联调

- 服务端：`docker compose up -d`，地址 `http://127.0.0.1:8080`。
- 小程序：开发者工具内运行，服务地址填 `http://127.0.0.1:8080`，勾选「不校验合法域名」。
- 手机预览时把地址换成电脑局域网 IP（`http://192.168.x.x:8080`），同样勾选不校验。

### 5.2 局域网（不备案，最快可用）

- 服务端部署在内网主机，`-p 8080:8080`。
- 小程序「服务地址」填 `http://内网IP:8080`（缺协议会自动补 `http://`）。
- 需勾选「不校验合法域名」；**仅适合开发版/体验版自测，不能上正式版**。

### 5.3 公网（正式可用）

两种方式，任选其一：

**A. 有公网 IP 的服务器（推荐）**

1. 域名解析到服务器，申请证书（或交给 nginx/caddy 自动签）。
2. 反代 `443 → 127.0.0.1:8080`，注意：
   ```nginx
   client_max_body_size 512m;     # 必须大于「单文件上限」，否则大文件 413
   proxy_read_timeout 300s;
   ```
3. **容器加 `-e TRUST_PROXY=true`**，否则审计记录与登录锁定会把所有人当成同一个 IP。
4. 小程序 BASE 填 `https://你的域名`，并配置 4.3 的合法域名。

**B. 内网机器 + frp 穿透（无公网 IP）**

后台「中转对接」页五步向导：

| 步骤 | 动作 |
| --- | --- |
| 1 模式 | 选「单端口 443（wss 复用）」——小程序只认 https+443 |
| 2 域名/BASE | 填已备案域名，`https://print.你的域名.com` |
| 3 云服务器 | 填 frps 地址/端口/Token → 页面生成 `frps.toml`，复制到云上 `/etc/frp/frps.toml`。**wss 模式不要开 frps 的 `transport.tls.force`**（TLS 由 nginx 终结） |
| 4 nginx | 把生成的片段放到云上 `conf.d`：`/~!frp` 转 `127.0.0.1:7000`，`/` 转 `127.0.0.1:18080`；同样要放宽 `client_max_body_size` |
| 5 自检 | 点「运行自检」：本机服务 / 打印机 / frpc 语法 / 进程 / 服务端连通 / BASE / 公网回连，**全绿后再勾「启用 frp」保存** |

frpc 由容器内 `entrypoint.sh` 守护（每 5s 检查 `/data/frp/enabled`），关掉开关会杀掉 frpc，无需手动运维。

## 6. 上线前必须确认的安全项

| # | 项 | 要求 |
| --- | --- | --- |
| 1 | **开发模式** | 必须**关闭**。开启时 `/api/mp/dev-login` 接受任意 openid，并可借管理员白名单自动提权 → 可冒用任意用户/管理员身份 |
| 2 | **TRUST_PROXY** | 放在 nginx 等可信反代后必须设 `true`；公网直连时**绝不能开**（可伪造 `X-Forwarded-For` 绕过登录锁定与限流） |
| 3 | **管理员密码** | ≥8 位含字母数字；改密会立即使其他设备的登录失效（会话纪元） |
| 4 | **登录锁定** | 默认 5 次失败锁 15 分钟，按 IP 生效。反代后未设 `TRUST_PROXY` 会让全站共用一个 IP，一次攻击锁死所有人 |
| 5 | **数据备份** | 当前备份接口是「checkpoint 后直接下载活动库」，并发写入下可能拿到撕裂副本。**建议停服或低峰期备份**，或直接拷贝 `data/` 目录（停服后） |
| 6 | **保留与清理** | 「系统设置 → 数据与维护」设保留天数；「打印机 → 历史清理」可手动清任务/CUPS 作业/落盘/源文件/扫描。自动清理每小时执行 |
| 7 | **服务重启** | 后台「重启 CUPS / Avahi / frp」依赖容器 entrypoint 守护拉起。**不要以 `node src/index.js` 裸跑**，否则点一次会永久杀掉打印服务 |
| 8 | **包体红线** | 主包 < 2 MB（当前约 219 KB）、总包 < 20 MB、隐私不强制授权 |

## 7. 升级与回滚

```bash
# 拉新代码后
cd Printgate-最终版/Printgate
git pull                      # 或替换源码
docker compose build          # 只改前端时加 --build-arg CACHEBUST=$(date +%s)
docker compose up -d          # 重建容器
docker logs -f printgate      # 观察启动日志
```

- 启动时会做两类迁移：① 结构变更只加列不改数据（`ensureColumns`）；② 若 `/data` 下存在旧版 `remote-print.db`，会自动一次性导入设置/用户/文件/任务（标记 `legacyMigrated`，不会重复执行）。**升级前仍建议先备份 `data/`**。
- 回滚：`docker compose down`，换回旧 tag 镜像后 `docker compose up -d`；数据卷保留即回到旧版数据状态。
- CUPS 队列配置在 `./cups`，回滚后队列仍在。

## 8. 运维与排障

### 常用命令

```bash
docker ps                                     # 容器状态与健康检查结果
docker logs -f printgate                      # 服务日志（entrypoint 会 tail app.log）
docker exec -it printgate sh
docker exec printgate lpstat -p -d            # 打印机与默认队列
docker exec printgate lpstat -o               # 当前任务队列
docker exec printgate tail -50 /var/log/cups/error_log
curl -fsS http://127.0.0.1:8080/api/health    # 健康检查
docker exec printgate du -sh /data/*          # 数据占用
```

### 报错对照表

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 小程序「网络异常，请检查服务地址或网络（当前：xxx）」 | 后端没起 / 端口不符 / 域名未加白名单 | 看提示里的当前地址；确认容器与端口；真机改用 IP 或 https 域名 |
| 小程序「请先配置服务地址」 | 运行时地址为空 | 登录页「服务地址配置」填写 |
| 小程序「账号待管理员授权」 | 新用户默认待审批 | 后台「小程序用户」放行，或加 OpenID 白名单 |
| 上传提示「文件超过上限」 | `maxFileMB` 限制 | 「系统设置 → 打印」调大；同时确认 nginx `client_max_body_size` 更大 |
| 上传 docx 提示先转 PDF | 镜像未启用 Office 转换 | `docker build --build-arg WITH_OFFICE=1` 重建 |
| 预览提示「源文件已清理」 | 超过保留期被自动清理 | 属预期；重新上传 |
| 任务一直「打印中」 | 队列暂停 / 打印机离线 / CUPS 未就绪 | 看 CUPS 队列；超过 6 小时会自动转失败 |
| 打印没出纸但显示已完成 | 先标记 printing，再由后台对照 CUPS 队列收尾；若作业从未进入队列需看重试 | 用「重试」重新提交 |
| 后台登录提示锁定 | 同一 IP 失败次数过多 | 等 15 分钟；反代场景确认 `TRUST_PROXY=true` |
| 预览只有第一页 | 预览接口返回首页渲染 PNG，不是完整阅读器 | 属预期；需要全文请下载原文件 |

## 相册保存失败：必须在小程序后台声明隐私接口

真机点「保存到相册」报：

```
saveImageToPhotosAlbum:fail api scope is not declared in the privacy agreement
```

这不是代码问题，是**《用户隐私保护指引》里没有声明「相册（仅写入）」**。微信自 2023 年起强制要求：
接口用到的隐私能力必须在后台声明，否则调用直接被拒。

### 后台操作（管理员，一次性）

1. 登录 [mp.weixin.qq.com](https://mp.weixin.qq.com) → 左侧 **设置** → **服务内容声明** → **用户隐私保护指引**
2. 点「更新」，在「收集的信息 / 使用的权限」里勾选：
   - **相册（仅写入）** —— 对应 `wx.saveImageToPhotosAlbum`，用途填「保存打印预览图片到手机相册」
